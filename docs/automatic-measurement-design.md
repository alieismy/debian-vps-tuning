## 范围与需求

目标用户为希望诊断 VPS、但没有自有 iperf3 对端的管理员。日常流程为查看计划、一次确认、自动选点、读取报告。公共节点只测直连路径，不能证明业务收益或服务商 policer。

## 实现设计

- 共享采集函数从 profile 模板提取至唯一模板片段；生成器将相同函数嵌入旧六份独立 profile 和新测量 runtime。旧独立脚本无需新增运行依赖，避免复制并维护两套解析规则。
- Python 标准库负责目录校验、有限发现、路径绑定、计划、调度、分析与证据提交；Shell runtime 负责现有 Linux 采集和单次 iperf3。新测量 schema 与旧 `VERIFIED` 状态分开，不读取或伪造受管 profile。
- 状态转换：计划 → 明确确认 → 新建私有目录 → 发现 → 固定端点 → 低速控制 → 递增速率重复测量 → 尾部控制 → 结算 → 摘要提交。失败保留 `INCOMPLETE`；预算耗尽可以形成明确的部分结果，不能形成已确认拐点。
- 每次流量尝试独立预留、成功按无 omit 的 sender bytes 结算、失败按预留保守结算。进程时间上限纳入预留估算；仍不包含协议、重传和服务商计费开销，不承诺精确账单硬上限。
- 目录是数据，不执行内容；不在运行时下载目录或脚本。端点参数使用 argv，DNS 固定到字面 IP，IPv4-mapped IPv6 规范化。输出目录不得存在，创建为私有权限；证据包含地址，公开前需脱敏。
- 退出约定：0 为报告完成（包括明确的部分/不确定结果），2 为输入或能力错误，非零失败保留现场；130/143 表示信号中止。账本结算失败保持占用并阻止完成声明。
- 无需恢复系统参数：测量没有相应写入。中断仅清理本次子进程；重新运行使用新证据目录与原窗口剩余额度，不恢复旧的活动样本。
