## 执行结果

| 场景 | 执行与观察 | 结果 |
|---|---|---|
| 无公网测速流量的正常事务 | 直接调用修复模块的 `begin → set_rate/assert_active(2/3/4 Mbps) → close`，每档短暂维持；未启动 iperf3 | `RESTORED`；`fq 8001:` 和全部参数恢复，账本未变 |
| SIGINT | 产品 `htb-sweep` CLI 自动选取公共 IPv4 节点；首个正式窗口内确认自有 iperf3 socket 已建立、HTB root overlimits 增长 7 后，向已核验身份的 owner 发送信号 | 退出 130；`RESTORED`；仅一个正式尝试 |
| SIGTERM | 同一 CLI 自动选取另一个公共 IPv4 节点；首个正式窗口内确认 socket 与 HTB overlimits 增长 9 后发送信号 | 退出 143；`RESTORED`；仅一个正式尝试 |

两次信号测试均采用 HTB 2/3/4 Mbps 计划、application cap 5 Mbps、最多两次协议尝试，并将调度期限收紧为 90 秒；实际各用一次协议短测，并在第一个 2 Mbps 正式窗口内中断，没有运行完整阶梯。节点分别选择、结果分别验收，未拼接成同一条路径的性能结果，也未用 loopback 替代真实出口。

每次结束均核对：

- 原 `fq 8001:` 句柄、全部 14 项 fq 参数、其他 qdisc/class 与执行前一致；独立键值对比通过。
- 17 项受管 sysctl、managed state 摘要、旧第一阶段账本摘要、boot ID、接口身份和 `dvt` 指向与本轮开始及上轮最终观察一致。
- 无本次采集或看护进程、无活动登记，流量 `reserved_bytes=0`。
- 两次中断均保留 `INCOMPLETE`、不生成 `COMPLETED`，离线报告正确拒绝不完整材料。
- 三份冻结恢复程序与固定候选源码摘要一致；checkpoint 保存并实际使用经目标解析器验证的 weights 兼容参数。
