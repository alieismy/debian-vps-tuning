# v0.1.0-rc.15 发布说明

发布日期：2026-08-30

状态：Release Candidate / Pre-release

## 变更摘要

rc.15 不改变 17 个受管 sysctl、BBR + 根 `fq`、自动缓冲矩阵、swap、journald、NOFILE 或 schema 4 管理状态。本候选实现两项运行控制：

1. 新增 `dvt-traffic-budget.sh` 事务账本。benchmark、`dvt probe`、TcpQuality 和 HTB rate-sweep 在开始流量前必须从同一窗口原子保留计划 payload；已知 sender bytes 在成功后提交，未知或失败流量按计划上界保守计入，余额不足时 fail-closed。
2. 新增 `dvt-migrate.sh` 持久 checkpoint/resume。它固定复制旧版和目标版 profile，校验状态与资产哈希，按 `rollback → reboot gate → target apply → reboot gate → verify` 推进；重启必须由操作者执行并以 boot ID 变化证明。

总控、六份生成 profile、installer、TcpQuality、HTB managed-state 绑定和 Release 资产统一为 `0.1.0-rc.15`。旧 tag、Release 和资产保持不可变。

## 安全与运行边界

- 预算只核算应用层 payload；TCP/IP、链路、重传和服务商计费差异仍未知，服务商面板额度是独立人工门禁。
- 未结算 reservation 不会自动释放。确定测试未发生后，仍需由操作者审查 ledger；不得通过删除 ledger 绕过窗口预算。
- TcpQuality 无可靠的内部实际总字节口径，必须显式给出 `TCPQUALITY_PLANNED_PAYLOAD_BYTES`，成功也按该上界保守结算。
- 迁移器不自动重启、不检查服务商控制台、不验证 3X-UI/Xray 或真实代理路径，也不充当状态缺失或损坏旧版本的通用卸载器。
- HTB 仍是研究专用、非持久化能力；rc.15 不授权永久整形或通用 UDP 调优。

## 验证状态

发布门禁包括：

- 六份 profile 与单一模板一致；
- Bash 语法、controller fixture、完整静态 fixture 和 HTB fixture；
- Linux root 下 installer 生命周期、预算并发/超额/保守结算 fixture，以及迁移两次 boot gate 的 checkpoint/resume fixture；
- pinned ShellCheck 0.11.0；
- `SHA256SUMS`、installer 固定摘要、PR/CI、tag、Pre-release 资产和公开重下载反向校验。

上述门禁只证明源码、fixture、Linux root 安装和公开发布完整性。目标 VPS 的真实 rollback/reboot/apply/verify、控制台恢复、严格服务验证和业务链路仍未在本候选发布过程中执行。

## 升级

先执行 rc.15 总控的只读 `update --target v0.1.0-rc.15`。维护窗口内可用：

```bash
dvt migrate prepare --checkpoint /var/lib/debian-vps-tuning-migrations/rc14-to-rc15
```

后续严格按命令输出和 [README](../../README.md#从-rc14-升级到-rc15) 推进；两个 reboot gate 均不得跳过。旧版固定 profile 执行自身 rollback 后，才允许目标 profile apply。
