# v0.1.0-rc.6

这是 `debian-vps-tuning` 首发候选版本的第六轮整改。目标 Debian 12 1C1G VPS 证明 rc.2 遗留的 `state.json` 是空 JSON 流，而 `qdisc-original.json` 完整；rc.3–rc.5 没有正确识别和迁移这一状态。

## 根因

rc.2 的初始 jq 构造器因保留字 `label` 编译失败，没有生成状态 JSON。Debian 12 的 jq 1.6 对空输入配合 `-e` 可能仍返回成功；旧写入函数随后把空临时文件替换成正式 `state.json`。因为失败发生在 `APPLYING` 之前，qdisc 快照已经生成，但 sysctl、journald、fq helper 和 swap 尚未写入。

后续版本只修正了 jq 变量名和部分错误提示，没有解决三个系统性问题：空输入校验依赖 jq 版本行为；状态更新函数各自实现临时文件和 rename；关键函数在 `||` 条件上下文中执行时仍依赖 Bash `set -e`。因此空状态继续被当成“存在但字段为空”的事务，参数比较、哈希比较和回滚诊断依次暴露错误。

## 修复

- 状态校验先检查文件非空，再用 slurp 强制恰好一个 JSON 对象和完整 schema；
- 每个 jq 生产过程先写临时文件并检查自身退出码，随后统一校验并原子替换；不再使用无法获知上游最终状态的流式 writer；
- phase、managed file 和 swap 所有权更新全部复用同一提交函数；
- apply 和 rollback 对关键步骤显式传播失败，不把 `set -e` 当成事务机制；
- 独立 preflight 与 apply 内部预检分流，恢复相同参数重复 apply 的幂等路径；
- 新增带显式确认的 `recover`，仅隔离已由历史证据确认的 rc.2 首次写入前空状态。

## 目标机恢复边界

当前目标机已有证据表明：空状态来自 rc.2 jq 编译错误；当时尚未进入系统写入；当前根 qdisc 与保存快照一致；外部 `/dev/dm-0` swap 不是脚本创建。上传 rc.6 后可使用 `ALLOW_EMPTY_STATE_RECOVERY=1 ... recover`。命令还会实时检查项目文件、`/swapfile-proxy`、fstab、fq helper 和 qdisc，任一安全门不成立即拒绝隔离。

## 发布边界

rc.6 仍是预发布版本。必须在目标机完成 recover、1000 Mbps preflight/apply/verify、重启后 verify、重复 apply 和 rollback，才能关闭这条真实运行缺陷；其他 Debian 12/13、1G/2G 矩阵仍需执行。
