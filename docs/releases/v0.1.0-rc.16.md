# v0.1.0-rc.16 发布说明

发布日期：2026-08-31

状态：Release Candidate / Pre-release

## 变更摘要

rc.16 不改变 17 个受管 sysctl、BBR + 根 `fq`、自动缓冲矩阵、swap、journald、NOFILE、schema 4、流量预算或 HTB 的非持久化边界。本候选只实现两项诊断与执行可靠性改进：

1. profile benchmark 的每个 iperf3 方向都在独立进程组内运行。默认硬超时为 `BENCHMARK_SECONDS + BENCHMARK_OMIT_SECONDS + 15` 秒，可用 `BENCHMARK_PHASE_TIMEOUT_SECONDS=1..300` 显式缩放；超时先发送 TERM，5 秒后仍未退出则升级到 KILL。`INT`、`TERM`、超时及其他失败均回收活动进程组，保留 `INCOMPLETE`，并按既有 ledger 规则保守结算未知流量。
2. `diagnose` 和 benchmark 增加 IPv4/IPv6 policy rules 证据。发现自定义规则时才展开对应地址族的 `route show table all`，并明确警告默认路由网卡发现不证明复杂策略路由拓扑可安全 apply。benchmark 将证据保存为 `policy-routing.txt` 并纳入 SHA-256 清单。

总控、六份生成 profile、installer、预算/迁移/TcpQuality 工具、HTB managed-state 绑定和 Release 资产统一为 `0.1.0-rc.16`。旧 tag、Release 和资产保持不可变。

## 安全与运行边界

- rc.16 没有吸收 tcpfit、NetShape、NetPilot 或历史脚本的扩张 sysctl、`initcwnd/initrwnd`、固定 MTU、RPS/RFS、UDP、MSS Clamp、CAKE 或永久 HTB。
- benchmark 硬超时是本地执行上限，不证明远端服务端、线路或服务商 policer 状态；超时后的实际计费流量仍可能与应用 payload 不同。
- 策略路由输出可能包含本机地址、table ID 和网关，只保存在操作者指定的 root-only 证据目录；发布材料不包含目标机运行输出。
- 自定义 policy rule 只会触发只读警告和附加证据。rc.16 没有扩展 `apply` 对多默认路由、VRF、多 WAN、fwmark 或非 `main` table 的支持。
- 迁移器不自动重启，也不替代服务商控制台、严格 3X-UI/Xray 验证或真实代理业务冒烟。

## 验证状态

发布门禁包括：

- 六份 profile 与单一模板一致；
- Bash 语法、controller fixture、完整静态 fixture 和 HTB fixture；
- 默认/自定义/不可读 policy rule 分类，以及仅在自定义规则时输出非 `main` 路由证据的 fixture；
- benchmark timeout 参数、元数据、持久证据清单、TERM timeout 124、KILL 升级 137 和进程组实际回收 fixture；
- Linux root installer、预算和 rc.15→rc.16 checkpoint migration 生命周期；
- pinned ShellCheck 0.11.0；
- `SHA256SUMS`、installer 固定摘要、PR/CI、annotated tag、Pre-release 资产和公开重下载反向校验。

上述门禁只证明源码、fixture、Linux root 安装和公开发布完整性。目标 VPS 的真实 rollback/reboot/apply/verify、真实 iperf3 信号/超时、策略路由拓扑、严格服务验证和业务链路仍未在本候选发布过程中执行。

## 升级

先执行 rc.16 总控的只读 `update --target v0.1.0-rc.16`。维护窗口内可用：

```bash
dvt migrate prepare --checkpoint /var/lib/debian-vps-tuning-migrations/rc15-to-rc16
```

后续严格按命令输出和 [README](../../README.md#从-rc15-升级到-rc16) 推进；两个 reboot gate 均不得跳过。旧版固定 profile 执行自身 rollback 后，才允许目标 profile apply。
