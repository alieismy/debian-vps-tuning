# v0.1.0-rc.14 发布说明

发布日期：2026-08-28
发布类型：Pre-release
状态：Git tag、GitHub Release 和公开资产的实际状态以对应 GitHub Release 页面为准

## 主要变化

- 新增显式带宽重配置入口：`dvt reconfigure --port <MBPS>`。它只接受 `100–1000` Mbps 的明确目标值，不采用默认值，也不把普通 `apply` 变成隐式改参入口。
- 重配置只接受由同一 rc.14 profile 管理且完整验证通过的 `VERIFIED` 状态。目标 profile、脚本版本、RTT、buffer 模式、受管文件所有权或当前运行配置不一致时，操作在写入前拒绝。
- 自动 buffer 状态按新端口重新推导；显式 `BUF_MAX` 状态保留原值。默认 200 ms RTT 下，100→200 Mbps 等有效 sysctl 值不变的场景只更新 sysctl 文件注释、管理哈希和状态，不重写运行时 sysctl；例如 2 GiB 档 200→500 Mbps 会把自动上限从 16 MiB 调整为 32 MiB，并只通过本项目 sysctl 文件应用相关参数。
- 重配置使用 root-only 固定备份、`RECONFIGURING` 临时状态、候选完整验证和原子 `VERIFIED` 提交。中断、sysctl 应用失败或候选验证失败时自动恢复旧 sysctl 与旧状态；恢复失败保留 `DEGRADED`、事务备份和失败证据，必须执行 `dvt recover`。
- 普通 `verify`、`rollback`、`preflight` 和 `apply` 不会越过未完成的重配置事务。`recover` 仍保留经显式确认的 rc.2 空状态隔离分支。
- 总控、六份 profile、installer、TcpQuality 工具版本和 HTB 实验器的 managed-state 绑定同步为 `0.1.0-rc.14`；状态 schema 仍为 4。

## 使用边界

```bash
dvt verify
dvt reconfigure --port 200
dvt verify
```

`reconfigure` 不重建 qdisc，不修改 swap、journald、NOFILE、路由、防火墙、DNS、MTU、代理服务或持久 HTB。完成后不强制立即重启，但仍建议在后续维护窗口重启并再次执行 `dvt verify`，把即时一致性与重启持久性分开验收。

同值重配置在完整验证后幂等返回，不创建备份或写入系统。不得手工编辑 `/var/lib/proxy-vps-tuning/state.json` 代替该操作。

rc.14 profile 不会直接接管 rc.13 状态。由 rc.13 管理的 VPS 必须先按固定 Release 的 `update`、旧版本 `verify/rollback`、重启和 rc.14 `preflight/apply/verify` 流程建立 rc.14 状态；后续端口变化才可使用 `reconfigure`。
