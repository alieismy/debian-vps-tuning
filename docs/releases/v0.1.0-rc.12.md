# v0.1.0-rc.12 发布候选说明

日期：2026-08-18
状态：Pre-release；Git tag、GitHub Release 和公开资产的实际状态以对应 GitHub Release 页面为准

## 结论

rc.12 不改变 rc.11 的主机调优参数，并增强性能测量、证据固化及厂商 sysctl 配置归属迁移。17 个受管 sysctl、BBR + fq、自动缓冲矩阵、swap、journald 和 NOFILE 保持不变；状态 schema 升级为 4，用于保存 `/etc/sysctl.conf` 迁移与恢复证据。

## 主要变化

- `benchmark` 新增可选的 `BENCHMARK_OUTPUT_DIR`。提供该变量时，目录必须是尚不存在的绝对路径；脚本创建权限为 `0700` 的目录并保存原始 iperf3 JSON、分方向摘要、运行元数据、总结果和核心证据 `SHA256SUMS`。
- `benchmark` 在发起连接前按显式 `BENCHMARK_RATE_CAP_MBPS` 或合法管理状态中的 `port_speed_mbps` 估算 payload 流量上界；估算数值、cap 来源、方向和时长进入 `benchmark-meta.json`。没有可信 cap 时只报告不可估算。
- 新增固定 Release 的 `install.sh` 和安装后 `dvt` 短命令。外层固定 installer SHA-256，installer 再固定发布清单摘要并逐项校验全部运行资产；安装到版本化 root-owned 目录并原子更新 `current`，但不自动执行调优或测试流量。
- 新增 advisory-only `dvt probe`：要求用户显式提供获授权 iperf3 endpoint，使用显式或 `VERIFIED` 状态的 100–1000 Mbps cap，固定单流并通过 `iperf3 --bitrate` 强制限速，执行 2–5 个重复样本，复用现有 JSON 窗口、精确 bytes、事务终态和哈希链，只输出中位数及人工复核状态。
- 新增 `dvt htb` 受限 wrapper，把现有 200 Mbps Debian 13 实验器收敛为 preflight、10 秒 smoke、status/stop、reference/sweep 和只读分析；candidate sweep 必须先校验 reference 证据并显式确认已经人工复核，仍不存在持久化 HTB 动作。
- 上传和下载分别生成 schema 2 结构化摘要，严格校验 iperf3 核心数字字段、sender/receiver 实际秒数、bytes/seconds/bitrate 算术、跨端字节容差及 before/after 计数器键集合；报告 sender 吞吐/重传/每 GiB 重传、主机全局 TCP/接口计数器增量和 qdisc 增量。存在 `mq` 叶子时汇总 leaf，否则汇总 root，避免重复计数。采集完整与测量窗口可分析性分离。
- 持久化 benchmark 采用 `INCOMPLETE → COMPLETED` 终态模型；结果绑定核心证据清单哈希，完成标记再绑定清单和结果哈希。manifest 失败不会留下 PASS 结果。
- 新增 `tcpquality-evidence.sh`。该工具只接受已审计 commit `5d1f85a6b8916b73ec0389dbc9b4ed4aa27dae01`、三个固定脚本哈希和固定 rootfs SHA-256，默认重复三轮；显式检查每项关键采集，校验节点 12 列 TSV schema，并保存每轮日志、原始 CSV、节点快照及其哈希、实际节点 URL、节点漂移和完整哈希清单。
- 非发布实验资产新增两阶段候选发现：默认只运行重复 HTB200 reference，人工复核后才可显式生成 180/190/195 candidate sweep。v0.4.0 qdisc 执行器允许临时 100–200 Mbit/s；所有速率发现阶段都使用相同 `HTB + fq` 拓扑，只改变 class rate/ceil。分析器以有效窗口的 sender Mbit/s 为主吞吐指标，任一窗口异常即输出 `REVIEW_BLOCKED` 且不生成 shortlist。`experiment-plan.sh` 继续只读生成后续正式 A/B/A、跨窗口反向复验、至少五分钟冷却和可选低速 A/C/A 控制计划。
- `preflight` 可将 `/etc/sysctl.conf` 中唯一且值严格为 `fq`/`bbr` 的厂商定义分类为可迁移基线，保持零写入并输出 `PASS_WITH_PROVIDER_SYSCTL_TRANSFER`。`apply` 在状态提交后备份完整原文件并原子注释相应定义；`verify` 校验原始备份和迁移后文件哈希；`rollback` 恢复原文件及安装前运行值。
- 已安装参数与新输入不一致时，`apply` 在写入前拒绝并明确给出两条路径：输入错误时按原参数重试或执行 `verify`；确需改参时显式 purge、重启，再按新参数执行 `preflight`/`apply`。
- 服务商镜像没有 `/etc/sysctl.conf` 时，不创建该文件，迁移状态为 `NOT_REQUIRED`，新状态中不存在文件的哈希和所有权元数据均记录为 `null`。校验器兼容修正前本地候选生成的完整 `0/0/000` 占位组合，以保留安全 `verify`/`rollback` 路径，但拒绝残缺组合。

## 安全与兼容边界

- rc.11 已管理的主机不能直接用 rc.12 `apply` 覆盖状态。如只需要新诊断能力，可在独立目录运行 rc.12 的只读 `diagnose`、显式授权的 `benchmark` 或独立 TcpQuality 工具。
- 只有只读 `UPDATE_PREFLIGHT=1` 可以接受合法的 rc.11/schema 3 状态；rc.12 创建和管理的状态必须是 schema 4。该兼容路径不写状态，也不允许跨版本 `apply`。
- 自动 sysctl 迁移仅适用于 `/etc/sysctl.conf` 中唯一、规范、相同值的 `net.core.default_qdisc=fq` 和 `net.ipv4.tcp_congestion_control=bbr`。不同值、重复定义、其他受管键、其他 sysctl 文件、符号链接和非 root 所有文件仍会阻断。
- `rollback` 只有在当前 `/etc/sysctl.conf` 哈希仍等于记录的迁移后哈希时才恢复原文件。检测到外部修改时拒绝覆盖，并将状态保留为 `DEGRADED`。
- 如需把配置生命周期迁移到 rc.12，仍须在维护窗口使用当前版本完成 `verify`、`rollback`、重启，再执行 rc.12 `preflight`、`apply`、重启和严格 `verify`。
- TcpQuality 包装层不调用主机包管理器，也不修改 sysctl/qdisc、防火墙、systemd、swap 或代理配置；固定上游的 `--all` 仍会访问节点、报告和测速端点并产生主动网络流量。
- `benchmark` 和 TcpQuality 输出包含可关联运行环境的信息。对外共享前必须脱敏 host、IP、hostname、boot ID、run ID、时间和第三方报告标识，同时保留脚本版本及 SHA-256。
- 流量估算是未计 TCP/IP/链路层开销的 iperf payload 预算，不等同于计费流量；旧 `benchmark` 默认仍不注入 pacing，只有同时设置 `BENCHMARK_ENFORCE_RATE_CAP=1` 和显式 `BENCHMARK_RATE_CAP_MBPS` 才传递 `iperf3 --bitrate`。多流时按官方逐流语义把总 cap 等分并记录每流 bps；`dvt probe` 固定单流并强制启用该路径。候选发现中的真实阶段上限由 HTB class rate/ceil 保证。HTB 计划生成器不执行计划，低速候选必须等 HTB200 reference 人工复核后显式另建计划和证据目录。

## 验证状态

- 本地生成一致性、故障注入 fixture、Bash 语法、固定 ShellCheck 0.11.0 和 Release 清单门禁已通过；最终候选生成后须重新执行这些门禁。
- 新增流量估算的显式 cap、管理状态 fallback、无 cap 和非法输入 fixture；新增 schema 2 有效/无效 iperf3 测量窗口 fixture、HTB200 reference、180/190/195 candidate sweep、异常窗口阻断 shortlist，以及 HTB 两周期/单周期/低速控制计划 fixture。真实网络流量和目标机 qdisc 行为仍须按独立门禁验证。
- 用户提供的 Debian 13、1C1G、200 Mbps rc.11 生命周期与固定 TcpQuality S1/S2 证据证明了测量改进需求，但不能替代 rc.12 最终哈希的目标机验证。
- Debian 13、1C1G、100 Mbps、10 GB ext4 目标机已完成 rc.12 修正前本地候选的错误参数拒绝、purge、apply、重启 verify 和幂等门禁，并证明缺失的 `/etc/sysctl.conf` 不会被创建。该运行暴露的问题已纳入候选；因修正改变 profile 哈希，仍须对最终候选重做哈希绑定复核。
- 发布后仍需从公开 Release 地址重新下载全部资产，核对 installer 固定摘要、`SHA256SUMS` 和逐资产摘要，再在目标 VPS 验证安装菜单、probe 预算门禁及至少一次受控证据采集。
