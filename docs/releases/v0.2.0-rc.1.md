# v0.2.0-rc.1 发布候选

状态：未发布。第一阶段固定提交已通过本地适用门禁、Linux CI 及单机低流量功能验收；本候选另增加[第二阶段临时 HTB](../temporary-htb.md)。第二阶段[真实 VPS 首轮验收](../temporary-htb-acceptance-2026-09-28.md)因 fq weights 解析问题未通过；修复后的[正常事务及公共路径信号复验](../temporary-htb-retest-2026-09-28.md)已经通过，完整 sweep 结果与业务效果仍未验收。具体状态见[验证说明](../validation.md)。第一阶段功能与运行边界见[自动测量说明](../automatic-measurement.md)；上位输入与验收追踪见[实现契约](../automatic-measurement-design.md)。

新增独立 diagnose/measure/report、固定公共目录、按预算执行的出向速率阶梯、首尾控制与明确的不确定结果。默认配置参数不变；旧 probe 与独立测量 schema 分开。六份 profile 仍是兼容的受管配置入口。

第二阶段新增 `htb-sweep` 与 `dvt.htb-measurement/1`：显式接口与上下界、预算内粗细扫、上界 reference、单根 fq 完整参数恢复、独立 watchdog 和失败保留。它临时影响整个接口出向流量，不启用持久整形，也不放宽受管配置支持矩阵。

第二阶段实现 `6fd5030` 的 [Linux CI](https://github.com/alieismy/debian-vps-tuning/actions/runs/36393226085) 已通过：73 项 Python、原生隔离 tc/iperf3 的正常/失败/看护/信号恢复、安装生命周期及 ShellCheck。隔离环境的配置可观测性与 receiver 背离仍正确阻止候选区间，详见验证说明；该 CI 没有覆盖目标机 iproute2 6.15 的 weights 解析行为或业务效果。

首轮 VPS 失败后新增完整 fq 恢复命令的无写入语法预检、iproute2 weights 解析兼容及 checkpoint 参数重放。修复提交 `1986dea` 的 [Linux CI](https://github.com/alieismy/debian-vps-tuning/actions/runs/36397718732) 已通过 79 项 Python、完整原生恢复、root 生命周期与 ShellCheck。后续固定 `f08fd8c` 已在目标机完成正常事务和公共路径 SIGINT/SIGTERM 的自动恢复及清理；此有限证据不证明完整扫描、root-zero 自动恢复分支、重启或性能收益。
