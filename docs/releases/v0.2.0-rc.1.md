# v0.2.0-rc.1 预发行说明

状态：待完成平台验收与发布。本版实现 tcpfit 研究后的三阶段路线：公共端点自动选点和独立测量、可恢复的临时 HTB 扫描、扩展平台的持久配置。运行范围与验证证据按下述固定版本记录，不构成性能收益承诺。

## 新功能

- [`diagnose`、`measure`、`report`](../automatic-measurement.md)：无需先 apply 或自建 iperf3 服务端；固定公共目录、有限 RTT 排序、有预算协议尝试、重复出向速率阶梯及首尾控制。测量保持 qdisc/sysctl 不变，旧 profile 专用诊断通过 `diagnose --managed` 使用。
- [`htb-sweep`](../temporary-htb.md)：自动选点、显式接口和速率范围、粗细扫描、首尾低速与上界 reference、资源/窗口/收发一致性检查、完整 fq 恢复及独立看护。临时影响接口全部出向流量，只接受可完整恢复的单根 fq，mq 仍须使用普通 measure。
- [跨平台持久配置](../platform-support.md)：Debian 12/13、Ubuntu 24.04 LTS，支持 x86_64/aarch64。保留六份固定 profile，新增三份 adaptive；至少 1 CPU、384 MiB RAM，adaptive 不设固定 CPU/RAM 上限。持久配置带宽接受 1–10000 Mbps，默认仍为 200 Mbps。
- adaptive 的单 socket 上限为 `min(256 MiB, max(16 MiB, RAM/32))`，按 BDP 选择且受资源封顶，默认不创建 swap。17 项受管 sysctl、BBR+fq 默认、所有权/事务和共享预算边界保持。

## 恢复修复与迁移限制

修复实际 VM 回滚发现的 TCP 原值快照缺陷：旧采集可能把 `tcp_rmem/tcp_wmem` 三元组截为首项，而内核接受单值写入后仍保留另两项。新版保存完整三元组，恢复前验证完整性，恢复后读回核对；失败保留状态。

**历史快照缺失的字段无法自动重建。** 新迁移器拒绝此类来源，不能通过删状态、猜默认值或运行旧版 rollback 绕过。安装新入口不迁移 managed state；旧版本核验与恢复仍要使用对应固定资产。恢复条件和处置边界见[旧状态与迁移](../platform-support.md#旧状态与迁移)。原 rc.19 及更早 tag/资产保持不可变。

另修复真实 VPS 上 iproute2 6.15 的 fq weights 恢复解析，以及低速短窗过量入队导致的 receiver 背离。正式 HTB 样本按当前档位发送，write block 有界，预算仍按完整 cap 预留。离线 probe 校准继续接受固定 profile，明确拒绝尚未定义动态资源预算契约的 adaptive 输入。

不声明可靠 policer 识别、高速/IPv6 测量、特定服务商大内存主机或代理业务性能通过。ARM64 使用 ARM runner 上的 QEMU/TCG，平台生命周期不等于用户业务 VPS 的升级验收。持久 HTB 未启用；仍须依据临时实验与业务对照单独决策。
