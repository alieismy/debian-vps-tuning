# v0.1.0-rc.5

这是 `debian-vps-tuning` 首发候选版本的第五轮整改，处理 Debian 12 1C1G、1000 Mbps 目标 VPS 在 rc.4 回滚中暴露的 `fq_codel` 命令重建和时间字段比较问题。

## 修复

- `tc` 文本输出可把数据包数量显示为 `limit 10240p`，但命令输入要求纯整数。本版本恢复为 `limit 10240`，并直接传递 `tc -j` 中的 `memory_limit` 字节整数；
- `target`、`interval` 和 `ce_threshold` 比较允许 ±1 微秒量化差异，避免把 5000/100000 与 4999/99999 误判为漂移；
- 快照文件缺失或哈希不一致时输出期望值和实际值；语义不一致时输出接口及保存/当前 JSON；命令失败时输出经过 shell 转义的完整 `tc` 命令；
- `preflight` 遇到既有管理状态时不再笼统报“通过”：已安装状态引导 `verify`，`SWAP_RETAINED` 引导显式 purge，异常事务引导先 `rollback`；
- 文档说明最小化 Debian 没有 `sudo` 时，已经登录 root 的用户应去掉 `sudo`。

## 已取得的目标机证据

Debian 12、1C1G、1000 Mbps 目标机在 rc.4 rollback 中保留 `DEGRADED` 状态；运行时恢复到 `cubic + fq_codel`，`tc` 显示 `limit 10240p`，JSON 时间为 4999/99999 微秒。该证据确认了 rc.4 的命令单位缺陷和严格时间比较缺陷，但附件没有成功输出完整 `state.json` 与 qdisc 快照内容，因此不能据此断言快照哈希和所有保存字段均正确。

## 发布边界

这是预发布版本。应先在该目标 VPS 用 rc.5 完成现有事务的 rollback，再执行 1000 Mbps preflight/apply/verify、重启后 verify 和重复 apply。若 rc.5 仍无法回滚，不得手工删除 `/var/lib/proxy-vps-tuning`；应保留脚本打印的哈希、语义 JSON 和失败命令用于下一轮诊断。
