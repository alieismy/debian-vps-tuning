# v0.1.0-rc.13 发布候选说明

日期：2026-08-24
状态：Pre-release；Git tag、GitHub Release 和公开资产的实际状态以对应 GitHub Release 页面为准

## 结论

rc.13 保留 rc.12 的实际主机调优值，修正的是 TcpQuality 测量基线和只读可观测性。17 个受管 sysctl、BBR + fq、自动缓冲矩阵、swap、journald、NOFILE 与 schema 4 状态结构均未改变；没有把 HTB、MTU/MSS 或额外 TCP 参数写入持久配置。

## 主要变化

- 固定 TcpQuality release `v1.00013`、commit `73606e2460bde21bb2e253842971f8ca8c9eb51c`、三个脚本、`rootfs-manifest.json` 和 amd64 rootfs。固定元数据还记录 rootfs 内 `libtcpquality-tcpinfo.so`、`tcpquality-retrans-seq.bt` 与 `tcpquality-retrans-skb.bt` 的路径、大小和 SHA-256。
- `tcpquality-evidence.sh` 要求显式选择 `TCPQUALITY_MODE=local-evidence` 或 `public-report`，并设置 `TCPQUALITY_ACK_TRANSIENT_FIREWALL=1` 确认上游 TOS 测速会临时创建/删除 `iptables`/`ip6tables` 目标计数链。本地模式固定使用 `--debug --no-rank-upload`；公开模式使用 `--debug` 并明确允许公开报告及附属 debug bundle 上传。
- 每轮必须产生且仅产生一个 CSV 和一个 debug archive。新增 `debug-inventory.tsv` 与 `retransmission-evidence.tsv`，保存指标来源、TCP_INFO 计数、eBPF 去重计数、分母、比例、回退原因和测量状态。
- `ebpf_seq`、`ebpf_skb`、`tcp_info_getsockopt`、`tcp_info_ss` 被标为流级证据；`nstat` 回退被标为 `MEASUREMENT_DEGRADED`。旧版本整机 `TcpRetransSegs` 增量与新版流级百分比不得串接为同一时间序列。
- TcpQuality 主机快照增加六个 TCP 参数、默认/参考出口、整机 CPU 计数、per-CPU softnet 计数和 `ss -s`。六份 profile 的 `diagnose` 只读增加相同 TCP 参数；当 `tcp_window_scaling` 或 `tcp_moderate_rcvbuf` 不为 `1` 或不可读时发出告警，但不改变受管键集合，也不自动修改主机。
- 版本同步到 `0.1.0-rc.13`，HTB v0.4.0 的 managed-state 版本门禁随之更新；实验拓扑、速率范围和非持久化边界不变。
- HTB rate discovery 升级到 plan/analyzer schema 3。runner 在任何流量前执行当前 profile 的只读 `verify`，冻结 managed profile、版本、状态、端口和 state SHA-256，并要求每个 `benchmark-meta.json` 与该绑定一致；candidate plan 同时绑定已人工复核 reference 的 manifest、analysis 和 completion 摘要。
- 每个 HTB 样本必须同时通过有效测量窗口、正 `overlimits`、最低 sender 速率暴露比例、CPU idle/steal、softnet drop/time_squeeze 和接口 drop/error 门禁；任一失败都输出 `REVIEW_BLOCKED` 和空 shortlist。
- 正式排程改为一个调用只生成一个带显式 `window-id` 的 `aba` 或 `bab` 三阶段窗口；反向窗口必须单独生成。`dvt htb` 使用并校验 `/usr/local/sbin/htb-aggregate-experiment` 稳定路径，避免 watchdog 因从 Release 版本目录直接启动而拒绝建立。
- 新增 VMISS Basic 1C1G / 200 Mbps 权威 campaign SOP，覆盖 5 样本 HTB200 reference、P1→P2→P4 暴露重试边界、180/190/195 sweep、两个独立窗口、`TCPQUALITY_RUNS=1` 和真实代理临时复验；旧 v0.2.1 SOP 仅作历史审计。

## 安全与兼容边界

- `local-evidence` 不上传公开报告或 debug bundle，但仍访问动态节点与测速端点、加载临时 eBPF 探针，并在宿主网络命名空间创建/删除计数链。`public-report` 还可能上传公网地址、节点地址、路由、测速明细及失败响应；两种模式都必须由操作者显式确认相应边界。
- debug archive 权限随证据目录保持 root-only，其中可能包含可关联主机和线路的信息；对外共享前应脱敏，不能只删除表层 CSV。
- rc.12 管理状态不能直接由 rc.13 `apply` 覆盖。先用 rc.13 `update --target v0.1.0-rc.13` 做只读检查；迁移时由 rc.12 执行 verify/rollback/purge 和重启，再由 rc.13 preflight/apply、重启并严格 verify。
- `nstat` 是整机网络命名空间计数，可能混入 Xray、SSH 和其他 TCP；降级结果只保留现场，不用于流级重传率或参数因果判断。
- 两个 TCP 默认值的只读告警不改变 `verify` 结果；`tcp_slow_start_after_idle`、MTU probing、TSQ 和 notsent low-water 仍只展示，不触发该告警。
- HTB reference、shortlist、双窗口和代理临时复验都不授权持久化。稳定执行器必须由 root 所有、非符号链接、不可被 group/world 写入；开始新实验时其 SHA-256 必须匹配当前 Release。事故恢复的 `status/stop` 仍优先使用已安装执行器，不因当前 bundle hash 漂移而静默替换活动工具。

## 验证状态

- 本地生成一致性、全部 Bash 脚本语法、控制器/静态/HTB fixture、十七项发布资产清单、installer 摘要链和 whitespace 门禁均已通过；静态 fixture 覆盖 `1C1G / 200 Mbps / 200 ms → 16 MiB`，以及两个 TCP 默认值的正常、异常、不可读和 `slow_start_after_idle=0` 不告警场景。
- HTB fixture 覆盖 schema 3 plan、reference/profile/state/benchmark 绑定、零 overlimits、低 offered load、高 CPU steal、畸形 CPU/softnet 计数拒绝、稳定执行器同/异 hash、独立 `aba`/`bab` window、旧 `--repeat-cycles` 拒绝和文档内关键函数 Bash 语法。
- 当前 Windows/MSYS 环境没有固定 ShellCheck 0.11.0；未运行 Linux root installer 生命周期，也未连接目标 VPS。
- 真实 TcpQuality 仍需在 Debian 目标机用完整 pinned 目录验证 eBPF → TCP_INFO → nstat 回退、debug archive 结构、上传边界、节点漂移和最终哈希链。
- 真实 VLESS + REALITY + TCP、iperf3、HTB200/candidate 和两个正式窗口未在目标机执行；本地实现与静态通过不能替代这些运行证据。
