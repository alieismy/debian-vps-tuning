# v0.1.0-rc.10（Pre-release）

rc.10 面向 1C1G/1C2G 主力 VPS，在保留 BBR + fq、事务回滚和资源边界的前提下，按内存档设置差异化 BDP 余量，并增加受校验的只读 update 检查、可复现增量诊断、Xray socket 选项可见性和用户显式授权的 iperf3 benchmark。状态 schema 保持为 3。

## 主要变化

- 自动缓冲按 512M/1G/2G 分别采用 `1×/1.25×/1.5×BDP`，再向上选择 16/32/64 MiB；
- 512M/1G/2G 的资源上限仍为 16/32/64 MiB；默认 200 ms 下，三个档位分别为 16/16/16/16（1000 Mbps 警告）、16/16/16/32、16/16/32/64 MiB；
- 200 Mbps 的 1G/2G 主力参数保持 16 MiB；500/1000 Mbps 的 2G 档分别使用 32/64 MiB；
- `diagnose` 默认采样 5 秒，输出 TCP、softnet 和 qdisc 增量证据，并只读展示队列、RPS/XPS、IRQ、网卡错误和 Xray sockopt；
- `benchmark` 只在显式提供 `BENCHMARK_HOST` 且主机已有 iperf3 时产生流量，不自动安装、改防火墙或选择公共服务器；
- 总控新增只读 `update`：自动发现同一 `major.minor` 发布线目标或接受 `--target`，校验当前/目标资产，执行当前 verify 和目标 update-preflight，并输出人工迁移材料；不执行 rollback/purge/apply/reboot；
- `verify`/`diagnose` 把缺少 `tcpFastOpen` 字段报告为“未显式配置”，不把内核 `tcp_fastopen=3` 误报为 Xray listener 已启用 TFO；
- `verify` 现在检查外部文件对受管 sysctl key 的重复归属，即使值相同也返回失败；`diagnose` 只读报告同一问题，受管文件及其符号链接不误报；
- 本地发布包完整性错误会明确提示可能混用了不同 Release；升级示例为每个版本使用独立临时目录，完整性失败仍不会自动回退联网下载；
- 不自动启用 RPS/RFS/XPS、IRQ affinity、CPU affinity、busy polling、ECN 或额外高风险 sysctl。

## 升级边界

rc.8/rc.9 的有效状态可由 rc.10 读取和回滚。先使用 rc.10 总控执行 `update --target v0.1.0-rc.10` 做只读兼容性检查；通过后在维护窗口使用已校验的当前版本执行 `PURGE_CREATED_SWAP=1 rollback`、重启，再使用目标版本执行 preflight/apply、再次重启和 verify。当前版本和目标版本必须使用不同的临时目录，不能混放总控、`SHA256SUMS` 和 profile。任一步失败都必须停止并保留状态；swapoff 失败时保留 swap、fstab 行和证据。已发布的 rc.9 资产不会被替换，因此旧 rc.9 总控本身没有 update action。旧 v5/v6 不具备同一状态所有权契约，必须按旧脚本归属退出，不能用 rc.10 rollback 猜测恢复。

`tcpFastOpen` 查询无输出不构成单独的升级故障，也不授权脚本修改 3X-UI 生成的 `/usr/local/x-ui/bin/config.json`。

## Release assets

发布时必须上传以下八个固定资产：

- `debian-vps-tuning.sh`；
- `debian12-1c512m-vps-tuning.sh`；
- `debian12-1c1g-vps-tuning.sh`；
- `debian12-1c2g-vps-tuning.sh`；
- `debian13-1c512m-vps-tuning.sh`；
- `debian13-1c1g-vps-tuning.sh`；
- `debian13-1c2g-vps-tuning.sh`；
- `SHA256SUMS`。

当前候选资产校验和以仓库根目录 `SHA256SUMS` 为准。Release 发布后必须从公开下载地址重新下载八个资产，在独立临时目录执行 `sha256sum -c SHA256SUMS`；通过前不得把公开资产验证标为完成。发布后不得移动 tag 或替换同名资产，发现缺陷时发布新版本。

## 当前验证状态

- 六份 profile 已由同一模板重新生成；
- Bash 语法、控制器 fixture、分档 BDP 资源矩阵、版本选择、跨版本 apply 拒绝、同值 sysctl 冲突、混合 Release 目录拒绝、诊断增量、benchmark 参数、状态构造以及既有事务/qdisc 故障注入已通过；
- ShellCheck v0.11.0 覆盖总控、六份 profile 和测试脚本；GitHub Actions CI 是发布门槛；
- 修复前候选哈希已取得 Debian 12 1C1G/100、200、1000 Mbps，Debian 12 1C2G/200 Mbps，以及 Debian 13 1C1G/1000 Mbps 的迁移、重启严格 verify 和重复 apply 证据；Debian 13 还完成 rc.9 swap 所有权退出和 rc.10 BBR/fq/swap 重启验证；
- 最终两项 Major 不改变写入参数，但重新生成后的哈希仅能在本地执行定向回归；没有 VPS SSH 凭据时，不把修复前真实结果冒充为最终哈希目标机验证；
- Release 发布后须从公开地址重下载并复核八个资产；最终哈希目标 VPS 复核、diagnose 业务采样和授权 benchmark 仍属于后续验证项。

## 发布边界

rc.10 仍是预发行版。静态检查和 fixture 不证明线路吞吐、延迟、丢包、3X-UI/Xray socket 选项、重启持久性或 VLESS + REALITY + TCP 业务体验。正式 `v0.1.0` 仍以 `docs/validation.md` 的目标 VPS 矩阵为准。
