# v0.1.0-rc.11（Pre-release）

rc.11 在不改变 rc.10 网络、swap、journald、NOFILE 和状态 schema 的前提下，补齐影响性能归因的只读证据，并提高授权 iperf3 基准的可复现性。现有 TcpQuality 样本显示，同一 rc.10 配置在约 8.5 小时内的组内波动大于或接近 v6 与 rc.10 第一次报告的组间差异；本版本不据此增加 sysctl，而是优先改进测量能力。

## 主要变化

- `diagnose` 增加整机 CPU user/system/softirq/steal 增量；
- `diagnose` 增加接口 RX/TX bytes、packets、drops、errors 和可识别 ethtool 错误计数增量；
- `diagnose` 在采样前后输出代理 service 主进程和直接子进程的 CPU time、RSS、线程数及 FD 数，不输出命令行；
- `benchmark` 默认每个方向先预热 3 秒并由 iperf3 `--omit` 排除，再记录 10 秒有效窗口；`BENCHMARK_OMIT_SECONDS=0` 可用于刻意包含 slow start 的短连接测试；
- `BENCHMARK_IP_FAMILY=auto|4|6` 可固定地址族，避免 DNS 地址排序变化混入 IPv4/IPv6 对比；
- 上传和下载分别输出 TCP、softnet、CPU、接口和 qdisc 证据；
- benchmark 阶段退出状态显式初始化，成功的首个上传阶段不再可能因空整数比较被误判为失败；
- `BENCHMARK_RUN_ID` 与自动元数据绑定脚本版本/hash、boot ID、profile、状态、网络参数和 iperf3 版本；
- 诊断和 benchmark 收到 `INT`/`TERM` 时清理本次 root-only 临时目录。

## 保持不变

- 受管 sysctl 仍为 17 个，写入值与 rc.10 相同；
- BBR + fq、资源档 BDP 系数、16/32/64 MiB 缓冲档、swap、journald、NOFILE 和 qdisc 状态/回滚语义不变；
- 状态 schema 保持为 3；
- 不启用 `tcp_slow_start_after_idle=0`、BBRv3/第三方内核、CAKE、固定 MTU/MSS、RPS/RFS/XPS、IRQ/CPU affinity、busy polling 或全局 IPv6 策略。

## 升级边界

rc.10 状态可以由 rc.11 只读检查，但 rc.11 不会在旧版本状态上直接 apply。先用 rc.11 总控执行 `update --target v0.1.0-rc.11`；通过后在维护窗口使用固定 rc.10 Release 完成 verify/rollback/purge 和重启，再在独立目录使用 rc.11 完成 preflight/apply、重启和严格 verify。两个版本的总控、`SHA256SUMS` 和 profile 不得混放。

只需要新增诊断能力时，可继续由 rc.10 管理现有配置，在独立目录直接运行匹配资源档的 rc.11 profile `diagnose`；该操作不迁移管理状态。benchmark 仍只在用户提供获授权服务端时产生流量。

## 验证状态

- 六份 profile 已从单一模板生成；
- 本地 Bash 语法、控制器、生成一致性、CPU/接口增量、benchmark 参数和既有事务/qdisc fixture 已通过；
- 已校验官方发布包 SHA-256，并使用固定 ShellCheck 0.11.0 完成总控、六份 profile、模板提取 helper 与测试脚本复核；
- rc.11 公开 Release 尚未创建，八个资产尚未从公开地址重下载复核；
- 最终哈希目标 VPS 的 diagnose、授权 benchmark、迁移/回滚生命周期和实际 VLESS + REALITY + TCP 业务矩阵待执行。

## 发布边界

rc.11 仍是预发行候选。静态检查不能证明 CPU steal、Xray RSS、网卡丢包或线路问题已经发生，也不能证明任何网络性能提升。新增计数用于区分候选原因，不应被单个非零值直接解释为根因。正式 `v0.1.0` 仍以 `docs/validation.md` 的目标 VPS 和业务性能矩阵为准。
