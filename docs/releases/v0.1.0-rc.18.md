# v0.1.0-rc.18 发布说明草案

状态：未发布实现候选

## 变更摘要

rc.18 修复 Linux 内核自动创建的 `mq 0:` 根 qdisc 的叶子寻址问题。`tc qdisc show`
可能显示 `fq_codel ... parent :1` 或 `parent 0:1`，但这些 parent 不能直接作为
`tc qdisc replace` 的稳定寻址目标。对于全部叶子均为 `fq_codel` 的拓扑，profile 现在先
选择一个与现有 qdisc handle 不冲突的非零 major，执行 `replace root handle MAJOR: mq`，
重新读取并核对队列 minor 集，再通过 `parent MAJOR:MINOR` 把当前叶子替换为 `fq`。

已经全部为 `fq` 的 `mq 0:` 不会为了规范化 handle 而产生写入。若 `mq 0:` 同时包含
`fq` 和 `fq_codel`，实现会在任何写入前 fail closed：根 `mq` 重建会重新创建叶 qdisc，
而保存的 `tc -j` 快照不足以保证恢复全部自定义 `fq` 参数，因此不能把这种拓扑当作
安全的自动转换路径。

回滚逻辑不再把保存快照中的 `:N`/`0:N` 直接传回 `tc`，而是用当前可寻址的 `mq`
根 major 与保存的队列 minor 重建 parent。qdisc 语义比较只在同一个 `mq` 队列内把
`:N`、`0:N` 和当前 `MAJOR:N` 规范化为同一队列标识；ingress、clsact 及其他 qdisc
仍按原始 parent 严格比较。

## 保持不变的边界

- rc.17 的 17 项受管 sysctl、资源感知 BDP 缓冲、默认 `BBR + fq` 和 managed-state schema 4 不变；
- benchmark phase summary 继续使用 schema 3，预算 ledger、迁移 checkpoint 和证据隐私边界不变；
- HTB 仍为非持久、显式授权、受预算约束的研究入口；rate、burst/cburst 和生产授权边界不变；
- 本候选不连接或修改真实 VPS，不运行公网测速，也不声称 OCI A1 驱动或重启生命周期已经通过。

## 当前验证状态

状态化 fake-`tc` fixture 覆盖 `mq 0:` 全 `fq_codel` 转换、全 `fq` 无操作、混合叶拒绝、
显式非零 `mq`、根重建失败、队列 minor 漂移及保存快照恢复。该证据只证明脚本控制流与
参数契约；真实 Oracle Cloud VM.Standard.A1.Flex 上的 `tc`、驱动队列变化、回滚、重启
持久性和代理业务仍须单独授权并取证。

PR、CI、tag、Pre-release 和公开资产反向校验均尚未执行。
