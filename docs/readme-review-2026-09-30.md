## 1. 结论与范围

**建议把 README 重构为按任务组织的项目入口，优先修正行为说明，再迁移详细操作与历史材料。** 当前材料的完整性、资产校验和恢复边界有价值，但同一页面同时承担入门、操作手册、参数参考、研究协议和历史迁移档案。新版能力已加入首段，后续主体仍保留较多旧版使用路径。

评估时的文档结论为**修改后可发布**：这是对拟重构 README 的质量判断，不是撤销现有 Pre-release，也不是代码或生产验收结论。以下 R1–R8、建议目录和当时检查结果保留为实施前基线；用户随后授权的重构及其验证结果由项目阶段备忘记录。

本次以 `rd-review` 的文章模式评估证据准确性与读者使用路径，以 `rd-research` 的证据支撑模式检查外部参考。完整阅读中文 README，检查英文的入口、章节结构、对应行为说明与同步声明，并核对关联源码、现有用户指南和文档门禁。没有执行 README 中的系统命令、连接 VPS 或重新验证运行性能。

置信度：R1–R3 的说明偏差为高（正文与源码直接对照）；推荐结构对读者效率的改善为中（官方指南与样本支持，尚无本项目用户测试）。

最强反对意见是：root 级工具应把恢复条件和校验步骤放在操作者容易看到的位置，拆文档可能让关键约束被漏读。该意见成立。因此建议保留首页的安装校验、旧状态停止条件、操作影响、预算及恢复入口，把长篇协议移走；不能只追求缩短行数，也不能把必要条件藏到多级链接之后。

## 3. 可复核的问题

静态统计已排除 fenced code block 内的 `#` 注释：中文 README 为 1222 行、52 个标题、52 个代码块；英文为 918 行、47 个标题、39 个代码块。两份文件的代码围栏闭合。行数仅描述现状，不单独构成缺陷。

### R1 — Major：默认 diagnose 的说明仍是旧入口语义

- **位置 / 评审轴：** [基线中文 README](https://github.com/alieismy/debian-vps-tuning/blob/c8fcfbcc4d2cd4bb40eeb7bbc594e1d07d9c3a61/README.md) 571–592 行、[基线英文 README](https://github.com/alieismy/debian-vps-tuning/blob/c8fcfbcc4d2cd4bb40eeb7bbc594e1d07d9c3a61/README.en-US.md) 555–575 行；证据准确性。
- **证据：** README 把默认 `diagnose` 描述为 5 秒增量采样，并给出 `DIAG_INTERVAL_SECONDS`、`DIAG_INCLUDE_SOCKET_DETAILS` 示例。[总控](../debian-vps-tuning.sh) 887–898 行实际把默认命令路由到 Python；只有 `diagnose --managed` 进入旧 profile 路径。[Python diagnose](../dvt-measure.py) 683–705 行输出能力快照，不读取这两个环境变量；[新指南](automatic-measurement.md) 已说明两者区别。
- **影响 / 分级理由：** 用户按文档复现业务采样，可能得不到其预期的时间窗口与代理进程证据；会实质影响诊断操作，故为 Major。
- **整改：** 首页区分 `dvt diagnose` 与 `dvt diagnose --managed`。旧增量采样、代理进程与 socket 详情示例改用明确的 managed 入口，并保留其受管 profile 范围；不改运行实现。

### R2 — Major：修改带宽的指引与回滚章节冲突

- **位置 / 评审轴：** 中文 README 925 行与 1175 行；一致性及证据准确性。
- **证据：** 前者要求服务商端口变更使用 `dvt reconfigure --port`；后者笼统要求新参数先 `PURGE_CREATED_SWAP=1 rollback`、重启并重新应用。[profile 模板](../tools/profile-template.sh.in) 489 行已区分“仅变更服务商端口带宽”和其他参数。
- **影响 / 分级理由：** 读者从回滚章节进入时，可能进行本不必要的撤销配置、swap 清理和重启。属于操作路径问题，故为 Major。
- **整改：** 明确三种情况：输错参数且尚未写入时无需回滚；同版本、同 profile、有效 `VERIFIED` 状态只改端口用 `reconfigure`；其他参数或跨版本变更按各自恢复/迁移流程处理。

### R3 — Major：不读取 Xray JSON 的表述与实际只读检查冲突

- **位置 / 评审轴：** 中文 README 417、424 行，英文 403、410 行；证据准确性。
- **证据：** “不会读取或修改……Xray JSON”与前文只读报告 `tcpFastOpen` 相冲突。[profile 模板](../tools/profile-template.sh.in) 2716 行起确实使用 `jq` 读取生成配置中的 TFO/keepalive 字段。
- **影响 / 分级理由：** 对管理员理解工具的数据访问范围有实际影响；不能用“不修改”替代“不读取”，故为 Major。
- **整改：** 分开说明“不会改写代理业务配置”和“特定验证/managed 诊断会只读检查生成配置的指定字段”。凭据处理边界继续保留，不把此问题扩展为安全扫描。

### R4 — Major：新版任务入口与适用条件没有贯穿首页

- **位置 / 评审轴：** 中文 README 3–23、41–50、250–297、595–627 行；读者路径及范围一致性。
- **证据：** 首段有新版链接和一个本地 `measure --plan-only` 示例，但安装后常用命令与本地命令列表未包含 `measure`、`htb-sweep`、`report`。后文主要展开要求显式对端的 `probe`/`benchmark`；统一“适用场景”实际对应持久配置。[独立测量指南](automatic-measurement.md) 明确按能力运行；[临时实验指南](temporary-htb.md) 另有单根 fq 等前置条件。

## 4. 建议的首页结构

首段可采用以下方向，实际措辞在实施时确认：

> Debian VPS Tuning 为 Linux VPS 提供主机网络诊断、有预算的公共 iperf3 自动测量，以及可验证、可回滚的 BBR + fq 配置。测量无需先应用调优，也支持临时 HTB 速率阶梯实验。当前版本为 `v0.2.0-rc.1` 预发行版；持久配置支持范围与测量能力条件分别列出。

标题附近放中文/English、当前固定 Pre-release 与文档导航。三项能力用短表说明，安装前就让用户知道该走哪条路径：

| 用户目标 | 入口 | 前提与影响摘要 |
|---|---|---|
| 查看当前主机能力与状态 | `dvt diagnose` | 无需先 apply；无主动测速流量、不改系统配置；旧增量诊断另用 `--managed` |
| 无需自建对端进行测量 | `dvt measure` | 按 Linux 能力和依赖检查；显式 cap/预算，公共选点；不改 sysctl/qdisc，报告写入本机 |
| 测试临时整形区间 | `dvt htb-sweep` | 单根 fq、可完整恢复；临时限制整个接口出向流量；结束必须核对恢复，不自动持久化 |
| 安装并管理主机调优 | `dvt preflight` → `dvt apply` | Debian 12/13、Ubuntu 24.04，x86_64/ARM64，原生 systemd 和实际内核能力；持久修改，有重启验证与回滚路径 |

建议章节顺序：

```text
项目名、语言入口、版本状态、简短定位
功能与操作边界（任务选择表）
支持范围与前置条件（区分持久配置与独立测量）
快速开始
  安装前：新主机 / 已有受管状态分流
  固定版本下载、SHA-256 校验与安装
  路径 A：只读诊断 → 有预算独立测量 → 查看报告
  路径 B：preflight → apply → 重启后 verify
默认低流量验收路径
常用操作（status、reconfigure、managed 诊断、更新检查）
升级与回滚（短说明、停止条件、完整指南链接）
验证状态与已知限制（当前摘要、完整证据链接）
文档导航（按任务，包含临时 HTB 和高级研究入口）
帮助、贡献与安全报告
许可证
```

不要求某个固定行数，也不建议用大量折叠块把原 1200 行正文原样塞回首页。HTB 不列为首次安装后的默认必跑步骤。新安装时，可把 `--no-launch` 用于“只安装”的分流，再让用户自行选择测量或持久配置；该参数已有实现，不需要新增安装模式。

必须保留的内容：固定 tag/URL 和 SHA-256 校验；安装不等于 apply 或状态迁移；旧 TCP 原始三元组缺失时停止；失败保留 state/checkpoint/ledger；普通 rollback 的 swap 语义；主动流量预算与公共端点隐私；临时 HTB 的全接口影响和恢复限制；公共测量不能证明可靠 policer、线路容量或代理收益。

## 6. 实施次序与验收条件

1. **先修事实与入口。** 处理 R1–R3，并核对每条命令、工作目录、前置状态、执行影响和预期结果。已有受管状态必须在安装/应用之前分流。
2. **再做分层迁移。** 先建立承接位置，再压缩首页；按上表追踪内容去向，不删除历史证据，不把历史命令自动改成新版本。源码、profile、manifest、安装器及已发布资产无需变化。
3. **同步双语与链接。** 两份 README 的核心路径和版本摘要必须相同；中文详细文档的语言状态显式可见。已知旧 README 锚点通过原标题或显式锚点加迁移链接保留。
4. **按文档改动验证。** 检查相对链接及片段、Bash 代码块语法、固定版本/摘要、两份首页关键语义和 diff。只校验语法，不执行文档中的公网测速或 root 配置命令。

已有约束不能在重排中丢失：

- [static-check.sh](../tests/static-check.sh) 56–60 行检查两份 README 的默认低流量验收标题和“旧版固定 Release”措辞；377 行检查 installer 摘要。可以保留这些简短要点；若因内容迁移调整断言，应检查新权威位置和首页指针，而不是删除门禁。
- [rc.15 发布说明](releases/v0.1.0-rc.15.md) 与 [rc.16 发布说明](releases/v0.1.0-rc.16.md) 链接旧迁移锚点；[独立测量指南](automatic-measurement.md) 链接 `#联网安装与验证`。迁移前清点全部仓库内入链，重要历史锚点保留兼容跳转；不改写旧 tag/Release 资产。
- 复用现有文档检查和仓库适用门禁。若后续改了静态门禁代码，再执行对应门禁；本次纯评估不触发新的 Linux/VPS 测试矩阵。

验收以任务能否完成为准：新用户能在首页识别“只测量”和“持久调优”的区别；从校验安装找到一个不需先 apply 的测量流程；老用户能找到状态兼容与拒绝恢复的条件；HTB 使用者能在执行前看到接口影响和恢复路径；中英文不会给出不同的关键操作语义。可用性改善属于待实施、待验证判断，本轮没有进行用户测试。

本轮复用了现有本地文档检查入口：101 个本地链接目标、94 个 Bash 代码块语法、24 项资产摘要及 installer/controller 的 README 固定值检查通过。另检查了评估报告与阶段备忘的相对链接目标，核对两份 README 的 SHA-256 未变，并执行 `git diff --check`。这些是文件与语法证据，不证明命令说明正确、网络端点可用或目标 VPS 已验收；历史锚点迁移门禁属于后续实际重排时的检查。
