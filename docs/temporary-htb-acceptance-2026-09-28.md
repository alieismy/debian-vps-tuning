## 根因与范围内修复

恢复命令末尾的标准 `weights W1 W2 W3` 在目标机返回 `Not enough elements in weights`。在不存在的接口上进行最小解析复现，排除了真实接口和网络负载因素；[iproute2 v6.15.0 的 `tc/q_fq.c`](https://github.com/iproute2/iproute2/blob/v6.15.0/tc/q_fq.c#L253) 显示 `weights` 分支在循环前及循环内均执行 `NEXT_ARG`，因此跳过第一个输入值。调整排列只改变报错，增加一个被跳过的 token 后才能正确读取三项权重。该行为也暴露了本项目的缺口：原实现识别 JSON 参数后，没有在开始整形前验证目标 `tc` 能否解析完整恢复命令。

修复包含三部分：

1. 写入任何 HTB 前，使用**没有 `dev` 参数且以 `help` 结束**的命令检验完整 fq 恢复语法；以同一 `tc` 的帮助输出作为精确对照，不产生接口写入。
2. 优先采用标准语法；仅遇到已识别的 `weights` 解析错误、且兼容候选完整解析成功时，采用多一个跳过 token 的形式。未知语法或其他错误在整形前拒绝。
3. 把通过验证的参数保存在 checkpoint；恢复时重放，并核对参数只能来自原 fq 快照的限定表示，恢复后仍逐项比较 fq 参数。

新增六项离线回归覆盖标准/受影响解析器、未知错误拒绝、写入前阻断、恢复参数重放及与原快照不符时拒绝；原生测试另检查语法预检不改变 qdisc。目标实际 iproute2 6.15.0 已通过修复后的**无设备参数解析检查**，前后 qdisc 一致。此检查与先前补救恢复共同支持修复机制，但不能替代修复候选的完整自动事务或信号验收。完整本地/CI 状态以[验证说明](validation.md)为准。
